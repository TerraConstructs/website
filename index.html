Why TerraConstructs

  • Level 2 Constructs for AWS services with strong defaults and sane service patterns.
  • Full IAM model with IGrantable, IPrincipal, and grants across L2s.
  • First-class Terraform ecosystem support. Leverage terratest, tflint, infracost, OPA, ... .
  • Built on CDKTF leveraging late binding, factory patterns and Aspects - flexibility modules can't match.
  • Advanced Construct Trees for DSLs such as StepFunctions, ECS Task Definitions and many more - lacking in the terraform-provider-aws resource model

Escape HCL Module Hell with CDKTF L2 Constructs

Compose AWS architectures using well architected L2 building blocks. Generate Terraform you can reason about, review, test, and ship.

IAM that makes sense

AWS CDK's aws-iam on Terraform, means grant Method support across the library. Finally control permissions in an intuitive and reliable way without losing full customization controls.

  • AWSCDK's grant methods for Terraform!
  • Predefined Grant Policies for common use cases
  • Unit-tested and Integration tested

Late Binding + Aspects

Adapt the generated Terraform at synth-time. Attach compliance Aspects to the construct tree - Achieve compliance TF Modules can't even fathom.

  • Environment-aware defaults
  • Stack-wide policy injection
  • Factory patterns for singletons

Asset Pipeline

The base AwsStack mirrors the AWS CDK asset flow using CDKTF Assets, S3 and ECR for advanced code staging and container building.

  • Deterministic hashes
  • Reproducible builds
  • Cacheable deploys
